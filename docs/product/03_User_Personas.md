# User Personas

**Project:** FraudShield AI  
**Product:** Real-Time Payment Fraud Detection Platform

---

# Why User Personas Matter

FraudShield AI is not built for a single user.

Different teams interact with the platform in different ways, each with unique goals, responsibilities, and challenges.

Understanding these users helps ensure every feature solves a real business problem rather than simply showcasing technology.

---

# Product Users

| Persona | Primary Goal | Uses Platform Daily |
|----------|--------------|--------------------|
| Fraud Analyst | Investigate suspicious transactions | Yes |
| Fraud Operations Manager | Monitor fraud trends and team performance | Yes |
| Risk & Compliance Officer | Ensure regulatory compliance and audit readiness | Frequently |
| Product Manager | Improve fraud strategy and customer experience | Frequently |
| System Administrator | Manage platform configuration and health | Occasionally |

# Persona 1 — Fraud Analyst

## Profile

| | |
|---|---|
| Role | Fraud Analyst |
| Experience | 2–8 Years |
| Department | Fraud Operations |
| Primary User | Yes |

### Responsibilities

- Investigate suspicious transactions
- Review fraud alerts
- Verify customer activity
- Decide whether to approve, decline, or escalate transactions
- Document investigation findings

### Goals

- Investigate cases faster
- Reduce manual effort
- Make confident fraud decisions
- Minimize false positives

### Pain Points

- Too many alerts
- Multiple systems to review
- Limited explanation behind fraud scores
- Manual investigation process
- Time pressure

### Success Looks Like

- Faster investigations
- Fewer clicks
- Better fraud decisions
- Clear explanations

# Product Manager's Perspective

Every feature should be traceable to a user need.

For example:

- AI Investigation Assistant → Helps Fraud Analysts.
- Fraud Dashboard → Supports Operations Managers.
- Decision Logs → Helps Compliance Officers.
- Analytics & KPIs → Supports Product Managers.
- Health Monitoring → Supports System Administrators.

If a feature doesn't solve a real user problem, it should not be part of the MVP.
